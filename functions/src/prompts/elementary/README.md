# 초등 생기부 교과학습발달상황 평어 생성 — 프롬프트 패키지

2026학년도 학교생활기록부 기재요령(초등학교)과 2022 개정 교육과정 성취수준을 근거로 한, API 호출용 프롬프트 모듈 묶음임.

---

## 1. 파일 구성

```

README.md                    이 문서
FILE_MAP.md                  한글 이름 ↔ 영문 파일명 대조표

data/                        ★ 이 저장소에는 반입하지 않음 (7절 참고)
  index.json                 학년군별 교과 목록과 파일 경로 색인
  achievement_G1-2.json      학년군 전체 (참고용 원본)
  achievement_G3-4.json
```

> 파일명은 영문이지만 **내용은 모두 한글**임. 한글 이름과의 대조는 `FILE_MAP.md` 참고.


### 예시집 유형 네 가지

| 유형 | 해당 파일 | 쓰임 |
|---|---|---|
| **활동 대응형** | 6학년 전교과_활동별 | 수업 활동명 하나에 문장 5개를 대응. 교사가 활동명만 입력했을 때의 생성 흐름 |
| **수준별 대조형** | 1학년 국어·통합, 4학년 체육, 6학년 국어·영어·미술 | 같은 평가요소를 상/중/하로 어떻게 다르게 쓰는지 학습 |
| **문장 은행형** | 1~3학년 대부분, 5학년 사회·영어·미술·음악·실과, 6학년 과학·도덕·음악·실과 | 단원·영역별 단문을 모아 둔 형태. 조합해서 한 학생 평어를 구성 |
| **완성 평어형** | 4학년 국어·수학·미술·영어, 5학년 다교과·체육, 6학년 체육 | 학생 1명분 완결 문단. 분량·영역 배분·개별화 정도의 기준 |

### 특히 중요한 세 파일

1. **`G5_multi-subject_standards-linked.md`** — 성취기준 → 평가요소 → 학생별 평어로 이어지는 연결이 명시되어 있음. AI가 따라야 할 근거 구조를 그대로 보여 줌
2. **`G6_all-subjects_by-activity.md`** — 활동명 → 문장 5개 대응이 10개 교과에 걸쳐 정리되어 있음. 교사 입력이 "활동명"뿐일 때 참조할 표
3. **`G6_pe.md`** — 앞 문장은 태도·참여도, 뒤 문장은 기능 습득으로 자리를 고정하고 각 자리 표현만 바꿔 300개를 만든 방식. §9 일괄 생성의 중복 회피 전략으로 유용함

### 수준 표기 대응

자료마다 수준 표기가 다름. 아래로 통일해서 해석함.

| 교육부 | 학교 현장 | 자료에 나타난 표기 |
|---|---|---|
| A | 상 | 매우 잘함, 잘함, 우수 |
| B | 중 | 보통, 양호 |
| C | 하 | 노력 요함 |

## 2. 호출 시 조립 방법

```
system  = 00_core_prompt.md
        + "\n\n# 성취기준·성취수준 데이터\n\n" + data/by-subject/{학년군}_{교과}.json
        + "\n\n# 평어 예시집\n\n"           + examples/{해당 학년·교과}.md   (있는 경우에만)

user    = 교사 입력 (학년/학기, 교과, 영역·단원, 성취수준, 관찰 기록)
```

> 이것은 원본 패키지가 상정한 범용 조립 레시피임. 이 저장소에서 실제로 어떻게 조립되는지는 7절 참고.

학년 → 학년군 매핑: 1·2학년 → `G1-2`, 3·4학년 → `G3-4`, 5·6학년 → `G5-6`

교과 영문 키: korean 국어, math 수학, social 사회, science 과학, moral 도덕, english 영어, pe 체육, music 음악, art 미술, practical 실과, bareun-life 바른 생활, seulgi-life 슬기로운 생활, jeulgeoun-life 즐거운 생활

교과 파일이 없는 경우(예: 1·2학년 '안전')에는 성취수준 데이터를 생략하고 코어 프롬프트 + 예시집만 주입함.

### 토큰 절약 팁

`by-subject` JSON 하나가 대체로 3~15KB임. 영역이 많은 교과(과학·사회·수학)는 교사가 단원·영역을 지정한 경우 **해당 영역 객체만 잘라서 주입**하면 호출당 토큰이 크게 줄어듦.

## 3. 데이터 스키마

`data/by-subject/*.json`

```jsonc
{
  "학년군": "3-4학년군",
  "교과": "국어",
  "영역": [
    {
      "영역명": "듣기·말하기",
      "성취기준별_성취수준": [
        {
          "성취기준코드": "[4국01-01]",
          "성취기준": "[4국01-01] 중요한 내용과 주제를 파악하며 듣고 그 내용을 요약한다.",
          "A": "중요한 내용과 주제를 정확하게 파악하며 듣고, 중심 내용과 세부 내용을 구분하여 자신의 언어로 요약할 수 있다.",
          "B": "...",
          "C": "..."
        }
      ],
      "영역별_성취수준": [
        {
          "수준": "A",
          "지식·이해": "...",
          "과정·기능": "...",
          "가치·태도": "..."
        }
      ]
    }
  ]
}
```

- `성취기준별_성취수준` — 개별 성취기준 단위 평어 생성에 사용
- `영역별_성취수준` — 한 영역 전체를 아우르는 학기말 종합 평어 생성에 사용

**A/B/C는 교육부 표기이며, 학교 현장에서 흔히 쓰는 '상/중/하'와 대응함** (A=상, B=중, C=하). 성취율 기준은 A 80% 이상, B 60% 이상 80% 미만, C 40% 이상 60% 미만임.

## 5. 예시집 출처와 주의

예시집 문장은 첨부해 주신 교사 작성 자료(hwp·hwpx·xlsm)에서 추출한 것임.

- 이 문장들은 **AI가 그대로 복사해서는 안 되는 참고 자료**임. 코어 프롬프트 §10에 그대로 복사 금지가 명시되어 있음
- 문장의 어휘 선택, 길이, 명사형 종결 방식, 성취수준별 강도 차이를 학습시키는 용도로만 주입함
- 교과서 출판사가 표기된 파일(아이스크림·천재·미래엔·지학사·교학사·동아·비상·와이비엠)은 해당 교과서를 쓰는 학급에 우선 매칭하면 단원명이 맞아떨어짐

### 원자료를 그대로 쓰면 안 되는 세 가지

1. **4학년 체육 수준별 자료의 '하' 문장** — "이해하지 못함", "어려워함", "~가 요구됨"처럼 결핍을 지적하는 표현이 섞여 있음. 코어 프롬프트 §6.2의 C수준 서술 원칙(할 수 있는 것을 먼저 쓰고 지원 조건을 덧붙임)에 맞게 다듬어야 함. 같은 C수준이라도 6학년 영어 자료는 "익히려고 노력함"처럼 잘 처리되어 있으므로 그쪽을 기준으로 삼을 것
2. **5학년 2학기 체육 영역 구분** — 건강·도전·경쟁·표현은 2015 개정 체육 영역명임. 2022 개정은 운동·스포츠·표현이므로 영역명을 바꿔 적용해야 함
3. **6학년 미술 자료의 마침표** — 원자료 문장 끝에 마침표가 없음. 입력 시 붙여야 함

### 아직 채워지지 않은 예시집

다음 파일은 두 차례 모두 전달되지 않았음(업로드 목록에는 있으나 실제 파일이 도착하지 않음). 다시 올려 주시면 같은 형식으로 추가함.

- 4학년 2학기 사회 평어
- 4학년 1학기 도덕 평어
- 평어 정리 최종 과학 41
- 2학기 수학 평어
- 2022개정 지학사 5학년 1학기 과학 교과평어 72개
- 5학년 1학기 도덕 평어

그 밖에 아직 없는 범위

- 3학년 수학 / 과학 / 도덕 / 체육
- 4학년 사회 / 과학 / 도덕
- 5학년 과학
- 6학년 수학 / 사회
- 학교자율시간 활동

다만 6학년은 `G6_all-subjects_by-activity.md`에 국어·도덕·수학·사회·과학·영어·음악·체육·미술·실과 10개 교과가 모두 들어 있어, 위 목록의 6학년 항목은 활동 대응형으로는 이미 채워져 있음.

## 6. 기존 프롬프트와 달라진 점 (확인 필요)

1. **엔터(Enter) 바이트** — 기존 프롬프트는 엔터 1회 = 2Byte로 되어 있으나, 2026학년도 **초등학교** 기재요령 [참고자료 07]은 **엔터 1회 = 1Byte**로 명시하고 있음. 코어 프롬프트에는 초등 기준인 **1Byte**를 반영했음
2. **글자 수 권장값** — 기존 300~500자에서 **200~400자**로 낮춤. 초등은 규정상 제한이 없으나 교사 검토 부담을 고려한 내부 UX 기준이므로, 서비스 정책에 맞게 조정 가능함
3. **금지 항목에 추가** — 교과학습발달상황 전용 금지인 K-MOOC·MOOC·KOCW, 방과후학교 활동, 유학 기간 기록을 새로 넣었음
4. **예외 허용 항목 추가** — 영재교육·발명교육 이수 내용, 도서명 포함 독서활동은 조건부 입력 가능하므로 별도 항목으로 정리했음
5. **일괄 생성 규칙 신설(§9)** — 4학년 영어 자료에 들어 있던 교사 작성 프롬프트(30명 일괄 생성 조건)를 바탕으로, 학급 전체를 한 번에 생성할 때의 조건 확인·평가요소 조합·중복 방지·출력 형식을 코어 프롬프트에 넣었음

## 7. 이 저장소에서의 실제 조립 방식

이 패키지는 `functions/src/prompts/`의 프롬프트 팩 하나로 편입되었고, `functions/src/prompts/index.ts`의 `selectPrompt()`가 조립을 담당함. 2절의 범용 레시피와 세 가지가 다름.

### 7.1 조립 순서

```
system = elementary/00_core_prompt.md
       + examples/{학년군·교과에 맞는 파일}.md 에서 발췌한 일부   (있을 때만)
       + _shared/90_output_subject.md                          (항상 마지막)
```

- `_shared/00_common.md`는 **주입하지 않음**. `00_core_prompt.md`가 이미 금지 항목·문체 규칙·바이트 기준을 초등 기준으로 더 상세하게 담고 있어 중복이기 때문임. `middle-pe`·`high-info` 팩은 반대로 공통 블록을 주입받음
- `_shared/90_output_subject.md`가 마지막에 붙어 `00_core_prompt.md` §8·§9.4의 텍스트 블록 출력 형식을 **무효화**함. 이 서비스는 Upstage Solar를 `response_format: json_schema, strict: true`로 호출하고 결과를 Zod로 검증하므로, 코어 프롬프트가 지시하는 `[평어 초안]` 형식으로 응답하면 파싱이 깨짐

### 7.2 `data/`를 반입하지 않은 이유

프론트엔드가 `src/data/curriculum.json`에서 성취기준 원문(`standards[]`)과 해당 A/B/C 수준 원문(`officialLevelText`)을 꺼내 호출 요청 본문에 이미 담아 보냄. `data/by-subject/*.json`을 또 주입하면 같은 정보를 두 번 전송하는 셈이라 토큰만 낭비됨. 서버가 성취기준을 직접 조회하는 구조로 바뀌면 그때 반입하면 됨.

### 7.3 예시집은 전체가 아니라 발췌로 주입됨

examples 34개 합계가 약 700KB이고 최대 파일이 84KB임. 호출당 `max_tokens`가 1400이고 문장 하나에 재시도·검증까지 도는 구조이므로 통째로 넣을 수 없음. `loader.ts`가 요청의 학년군·교과로 파일 하나를 고른 뒤, 성취수준(A/B/C)에 해당하는 절만 골라 글자 수 상한까지 잘라 주입함. 예시집을 "복사 금지, 결만 학습"으로 쓰는 원래 의도는 그대로 유지됨.

### 7.4 프롬프트를 수정할 때

`.md`가 단일 소스이며, 빌드 시 `functions/tools/generate-prompts.mjs`가 이를 `functions/src/prompts/generated/`의 TypeScript 모듈로 변환함. `npm run build`가 자동으로 선행 실행하므로 `.md`만 고치면 됨. 생성된 파일은 직접 수정하지 말 것.
